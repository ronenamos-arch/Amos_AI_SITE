![מדריך Jev AI המלא - מודל קבלת החלטות סמנטיות מבית TypeSafe](/images/blog/jev-ai-system-one-header.png)

אחד החוקרים המרכזיים שהשתתפו בבניית ChatGPT מבית OpenAI, דיוגו אלמיידה (Diogo Almeida), השיק לאחרונה דרך חברת **TypeSafe AI** מודל שונה לחלוטין מכל מה שהתרגלנו לראות בעולם הבינה המלאכותית: **מודל שלא מסוגל לייצר אפילו מילה אחת.**

בעוד שכל התעשייה ממוקדת במודלים שמייצרים טקסט, כותבים קוד, מסכמים מסמכים ומבצעים תהליכי חשיבה ממושכים טוקן-אחר-טוקן (System 2) — **Jev נבנה לתפקיד אחר ושכיח פי כמה: להחליט מה התוכנה צריכה לעשות הלאה (System 1).**

במאמר ומדריך מעשי זה נצלול לעומק הארכיטקטורה של Jev, נבין כיצד הוא מאפשר להוזיל עלויות ריצה עד פי 400 ולהאיץ זמני תגובה עד פי 200, נסקור 3 מקרי בוחן מוכחים מהשטח, ונלמד כיצד לשלב אותו במערכות תוכנה ואוטומציה פיננסית.

---

## מה זה Jev AI ואיך הוא עובד?

רוב מוצרי ה-AI כיום מבוססים על מודלי שפה יוצרים (Generative LLMs) כמו Claude 3.7 Sonnet, GPT-5 או Gemini 2.5 Pro. כאשר אנחנו שואלים אותם שאלה של סיווג, ניתוב או קבלת החלטה, הם מחוללים טקסט מילולי, שממנו קוד המערכת צריך לחלץ JSON או מחרוזת מתאימה.

תהליך זה יוצר 4 בעיות יסוד במערכות ייצור (Production):
1. **זמני השהיה (Latency גבוה):** יצירת טוקנים בזה אחר זה לוקחת שניות יקרות.
2. **עלויות טוקנים גבוהות (Output Token Cost):** תשלום על טוקנים של פלט עבור כל צומת החלטה.
3. **סיכוני פורמט והזיות (Formatting Risk):** המודל עלול לסטות מהסכמה הנדרשת או להמציא ערכים.
4. **עומס חישובי מיותר:** הפעלת עשרות מיליארדי פרמטרים רק כדי לבחור בין A, B או C.

![ארכיטקטורת Jev AI - שכבת בקרה סמנטית בין קוד דטרמיניסטי למודלי שפה](/images/blog/jev-ai-architecture-overview.png)

### Jev משנה את המשוואה:
* **קלט:** מקבל טקסט ומצב מערכת (State) יחד עם סט מוגדר מראש של אפשרויות בחירה (Bounded Enum).
* **פלט:** מחזיר מידית אך ורק את הבחירה שנבחרה + רמת ביטחון מכוילת (Calibrated Probability / Confidence).
* **עלות:** **\$0.042 בלבד למיליון טוקנים של קלט — והפלט חינמי לחלוטין!**
* **מהירות:** זמני תגובה של אלפיות שניה בודדות.

> 💡 **האנלוגיה המובילה:** חשבו על Jev כעל `switch statement` חכם במיוחד — מסווג נתונים פשוט עם אינטליגנציה וגמישות של שנת 2026.

## המעבר מחשיבה איטית (System 2) לחשיבה אינטואיטיבית (System 1)

בפסיכולוגיה קוגניטיבית של דניאל כהנמן:
* **System 1 (מערכת 1):** החלטות מהירות, אינטואיטיביות, חסכוניות באנרגיה שמזהות תבניות מידית (זיהוי שלט עצור, סיווג כוונה, ברירת מחדל).
* **System 2 (מערכת 2):** חשיבה מאומצת, איטית, רפלקטיבית ומעמיקה (פתרון משוואה מתמטית מורכבת, תכנון מודל תזרים רב-שנתי).

עד היום, כל סוכני ה-AI והמערכות האוטומטיות נאלצו להפעיל מודלי System 2 כבדים ויקרים עבור כל החלטה קטנה: *"האם השאילתה הזו דחופה?", "האם הנתון חריג?", "איזה כלי יש להפעיל כעת?"*. 

Jev מספק לראשונה את שכבת ה-**System 1 האמיתית** עבור עולם פיתוח ה-AI.

## 3 מקרי בוחן מוכחים מהשטח

תוך שבוע בודד מהשקתו, Jev שולב ב-Vercel AI Gateway, OpenRouter, וב-Cloudflare Workers AI. שלושת מקרי הבוחן הבאים מדגימים את העוצמה שלו במגוון עולמות תוכן:

### 1. ניתוח וסיווג 724 פרסומות ב-40 שניות בעלות 9 סנט (מת'יו ברמן)
מת'יו ברמן (Matthew Berman) השתמש ב-Jev כדי לנתח ולסווג 724 פרסומות חיות מ-37 מותגים מובילים לפי Hook, פורמט, סוג ההצעה (Offer), קריאה לפעולה (CTA), שלב המודעות (Awareness Stage) והתאמה לדף הנחיתה.

![הדגמת ניתוח וסיווג פרסומות עם Jev AI - מתיו ברמן](/images/blog/jev-ai-ads-analysis-demo.png)

* **התוצאה:** הניתוח המלא של כל 724 המודעות הסתיים תוך **40 שניות** ובעלות כוללת של **9 סנט בלבד**.
* **הערך המרכזי:** במקום תיקיית קבצים סטטית ומבולבלת, המערכת הפכה את כל המאגר למסד נתונים סמנטי שניתן לשאילתות ופילוח מיידי.

### 2. בקרת עומק חשיבה דינמית בסוכן קוד (Vechen & OpenAI Codex)
המפתח Vechen שילב את Jev בתוך סביבת ריצה פעילה של Codex כדי לנטר את פעולת המודל. Jev בדק בכל שלב אם הסוכן תקוע:
* כשהסוכן הסתבך — Jev העלה את רמת ה-Reasoning Effort של GPT-6 Astra.
* בשלבים רוטיניים ופשוטים — Jev הוריד את רמת החשיבה למינימום.

![שליטה דינמית בעומק החשיבה של מודלי שפה בעזרת Jev](/images/blog/jev-ai-codex-reasoning-demo.png)

* **התוצאה:** **חיסכון של 50% בעלויות המודל**, קיצור משמעותי בזמני הריצה, ושמירה מלאה על ה-Prompt Cache.
* **המשמעות:** במקום לקבוע מודל קבוע מראש, Jev שולט ברמת האינטליגנציה המופעלת בכל שלב ושלב במשימה.

### 3. בוט מסחר תדירות גבוהה בבלוקצ'יין Monad (ג'רוד וואטס)
ג'רוד וואטס (Jarrod Watts) חיבר את Jev לעדכון מחירים בזמן אמת של צמד המסחר MON-USDC ובנה בוט מסחר מבוסס בינה מלאכותית. Jev מקבל את נתוני ה-Price Feed, מחליט האם לקנות או למכור, והבוט מבצע את הפקודה בפועל ב-Order Book של Kuru על רשת Monad.

* **התוצאה:** קבלת החלטת מודל וביצוע פקודה בתוך חלון של **בלוק בודד (300 מילישניות)**.
* **המשמעות:** הוכחה מעשית שניתן להריץ החלטות מודל AI בתוך לולאות מהירות וקריטיות לזמן אמת.

## הדפוס הארכיטקטוני האחיד: State + Question + Judgment

למרות שהדוגמאות לעיל נראות שונות לחלוטין, כולן מיישמות את אותו דפוס הנדסי פשוט וחזק:

![לולאת קבלת החלטות סגורה ומנוהלת עם Jev AI](/images/blog/jev-ai-decision-loop-demo.png)

```mermaid
flowchart LR
    State["1. יצירת State מוגדר (קוד)"] --> JevQuery["2. שליחת שאלה תחומה ל-Jev"]
    JevQuery --> JevResult["3. החזרת החלטה ספציפית + רמת ביטחון"]
    JevResult --> LogicGate["4. קוד המערכת בוחן Threshold ומבצע פעולה"]
    LogicGate --> NextAction["5. הפעלת מודל כבד / פקודת DB / אישור אנושי"]
```

## איך ליישם את Jev במחלקות כספים ו-FP&A

עבור מנהלי כספים, חשבים וצוותי FP&A, מודלים כמו Jev פותחים צוהר לאוטומציות שעד כה היו יקרות או איטיות מדי ליישום:

| צומת החלטה פיננסי | הגישה הישנה (LLM מלא) | הגישה המודרנית עם Jev |
| :--- | :--- | :--- |
| **סיווג הוצאות וחשבוניות** | שליחה ל-Claude/GPT (\$0.01-0.03 לחשבונית, 3 שניות) | סיווג מיידי ב-Jev לפי רשימת סעיפי תקציב (\$0.00004 לחשבונית, 50ms) |
| **זיהוי חריגות בתזרים** | פרומפט שבועי שקורא את כל הנתונים | לולאת בדיקה רציפה שמזהה אנומליות ומעבירה ל-CFO רק מקרים חריגים |
| **ניתוב שאילתות עובדים** | מודל שפה שמנסח תשובה מחדש | Jev מזהה האם השאלה היא יתרת ימי חופשה, פוליסת נסיעות או בקשת רכש |
| **אימות סמנטי לפני שליחת דוח** | בדיקה ידנית או קריאת LLM נוספת | Jev מוודא שסיכומי השורות מתאימים לסעיף הראשי בדוח הניהולי |

## דוגמת קוד מעשית: אינטגרציה עם Jev ב-TypeScript

להלן דוגמה לשימוש ב-Jev באמצעות קריאת API פשוטה:

```typescript
import { createOpenAI } from '@ai-sdk/openai';
import { generateObject } from 'ai';
import { z } from 'zod';

// קריאה ל-Jev דרך ה-Gateway של Vercel או OpenRouter
async function classifyFinancialTransaction(description: string, amount: number) {
  const response = await fetch('https://api.typesafe.ai/v1/decide', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.JEV_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      state: {
        vendor_name: description,
        amount_ils: amount,
        department: "Marketing"
      },
      question: "לאיזה סעיף תקציבי שייכת ההוצאה הזו?",
      options: [
        "Digital_Advertising",
        "Influencer_Campaigns",
        "SaaS_Software",
        "Travel_And_Entertainment",
        "Unknown_Requires_Review"
      ]
    })
  });

  const result = await response.json();
  // מחזיר: { decision: "Digital_Advertising", confidence: 0.98 }
  return result;
}
```

## מתי לא להשתמש ב-Jev?

למרות היעילות המרשימה, חשוב להכיר את גבולות הגזרה של Jev:
* ❌ **כאשר נדרש ניסוח טקסטואלי:** סיכום פגישות, כתיבת מיילים או ניסוח חוות דעת מקצועית.
* ❌ **כשאין מרחב החלטות מוגדר:** שאלות פתוחות ללא אפשרויות ברורות.
* ❌ **כאשר נדרשת הנמקה מורכבת בת מספר שלבים (Multi-step Reasoning):** במקרים כאלה עדיף להשתמש במודלי חשיבה ייעודיים כמו Claude 3.7 Sonnet או o3-mini.

## סיכום

Jev מסמן את תחילתו של עידן חדש בארכיטקטורת AI: הפרדה ברורה בין **שכבת קבלת ההחלטות והניתוב (System 1)** לבין **שכבת היצירה וההנמקה המעמיקה (System 2)**. 

שילוב נכון של Jev במערכות הארגוניות מאפשר לצוותי פיתוח וכספים לבנות סוכנים מהירים יותר, יציבים יותר, ובעלויות הנמוכות במאות אחוזים מכל פתרון מסורתי.
